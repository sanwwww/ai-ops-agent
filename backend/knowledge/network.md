# 网络故障排查知识库

## DNS 解析失败排查
DNS 解析失败的典型表现是 `gethostbyname` 报错或 `nslookup` 无响应。排查顺序：1) 先换一个已知正常的域名（如 baidu.com）测试，判断是本机 DNS 问题还是目标域名问题；2) 检查本机配置的 DNS 服务器（Windows 用 ipconfig /all，Linux 看 /etc/resolv.conf）；3) 尝试改用公共 DNS（114.114.114.114 或 223.5.5.5）对比；4) 用 `nslookup 目标域名 8.8.8.8` 指定权威 DNS 验证。若公共 DNS 能解析而本地 DNS 不能，说明是运营商或企业内网 DNS 的记录问题。若所有域名都解析失败，优先怀疑本机网络或 DNS 服务本身。

## DNS 能解析但网站打不开
DNS 正常但访问失败，说明问题在 DNS 之后的链路。依次检查：1) 网络连通性（ping 目标 IP）；2) 端口是否开放（80/443）；3) HTTP 服务是否响应。这类问题最常见的原因是：目标服务器宕机、防火墙拦截、或本地代理软件劫持了流量。浏览器配置了代理但代理服务挂掉时，也会出现"能解析、打不开"的现象。

## ping 不通的分层判断
ping 不通不一定是故障，要分层判断：1) ping 域名失败但 ping IP 成功——是 DNS 问题，不是连通性问题；2) ping IP 也失败——可能是网络断了、路由问题、或对方禁 ping；3) example.com、github.com 等走 CDN 的目标经常屏蔽 ICMP 回包，ping 无回包属正常现象，不算故障，此时应该用端口检测（telnet 或 TCP 连接测试）代替 ping 来判断服务可用性。判断顺序永远是：先 ping IP 判连通性，再 ping 域名判 DNS，不要混为一谈。

## 端口不通排查思路
TCP 端口连不上的原因按可能性排序：1) 目标服务没启动（最常见，先确认进程在监听：Linux 用 ss -tlnp，Windows 用 netstat -ano）；2) 服务监听在 127.0.0.1 而不是 0.0.0.0，导致外部连不上——服务日志和监听地址要对起来看；3) 防火墙/安全组没放行端口（云服务器要检查安全组规则）；4) 中间网络设备拦截。区分手段：从服务器本机连 localhost:端口 成功、从外部连失败，就说明是监听地址或防火墙问题，而不是服务本身的问题。

## 常用端口及对应服务
22 SSH 远程登录；80 HTTP 网页；443 HTTPS 网页；3306 MySQL 数据库；6379 Redis 缓存；8080 常见的应用服务（Tomcat/代理）；53 DNS 服务。排查时先确认目标服务理论上该监听哪个端口：网站是 80/443，数据库是 3306，不要拿 80 去测数据库是否存活。

## HTTP 5xx 错误定位
5xx 是服务端错误，说明请求已到达服务器但服务内部出错。502 Bad Gateway：网关（通常是 Nginx）后面的应用没响应或挂了，重点查应用进程是否存活、应用端口是否监听；503 Service Unavailable：应用过载或在发布/重启中，看负载和应用日志；504 Gateway Timeout：后端处理太慢超过网关超时时间，重点查慢查询、慢接口。定位顺序：先看 Nginx error.log，再看应用自身日志，最后查应用依赖（数据库/缓存）是否可用。

## HTTP 4xx 错误定位
4xx 是客户端错误：401 未认证（token 缺失或过期）；403 已认证但无权限（或 WAF 拦截）；404 路径不存在（检查 URL 拼写、路由配置、Nginx rewrite 规则）；429 请求过于频繁（限流触发）。404 排查技巧：先用 curl 直接请求确认是服务端问题还是前端跳转问题。

## SSL 证书问题排查
浏览器提示证书错误时的排查点：1) 证书过期——用浏览器或 openssl s_client -connect 域名:443 查看有效期；2) 证书域名不匹配——访问的域名和证书签发的域名不一致；3) 证书链不完整——部分安卓客户端会报错但桌面浏览器正常；4) 系统时间错误导致证书被判定无效。命令行快速验证：curl -v https://目标地址，看握手阶段报什么错。

## 网络延迟高排查
延迟问题的定位方法：1) ping 看基础 RTT，和正常时段对比；2) 用 mtr 或 tracert 看每一跳的延迟和丢包，定位是本地网络、运营商还是目标机房的问题；3) 网站整体慢但 ping 正常，问题多半在应用层（数据库慢查询、接口逻辑慢），用浏览器开发者工具看 TTFB（首字节时间）区分网络慢还是服务慢。

## CDN 目标 ping 不到回包的说明
很多大型网站（如 example.com、github.com、各类 CDN 加速站点）的边缘节点会禁用 ICMP 协议或对 ICMP 限速，表现为 ping 丢包率 100% 或超时，但网页访问完全正常。这不是故障。运维判断这类目标是否存活的标准做法是改用 TCP 探测：检测 443/80 端口能否建立 TCP 连接，或直接发 HTTP 请求看状态码。AI 运维助手遇到 ping 无回包时，应继续做端口和 HTTP 检测再下结论，不能只凭 ping 判断宕机。
